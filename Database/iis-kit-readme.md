# PMO Навигатор: комплект для IIS

Это опубликованная сборка с календарём, отпуском по датам, поиском, фильтром типа сотрудника и ограничениями прав. План-факт в этой версии не дорабатывался. На внутренний сервер переносить только после пользовательской проверки на Render.

## Что находится в архиве

- **app:** DLL и зависимости, статические файлы интерфейса, миграции. Это результат `dotnet publish`, не только исходники.
- **appsettings.example.json:** пример конфигурации без пароля и строки подключения. Для новой установки скопировать в appsettings.json и заполнить. Для обновления существующие настройки сохранить и дополнить новыми параметрами.
- **web.config.example:** пример конфигурации IIS. Существующий web.config не перезаписывать вслепую: сохранить настройки авторизации и виртуального пути.
- **Календарь-и-права.md:** источник календаря, формат CSV, расчёт отпуска, ограничения и настройка ответственных.
- **BUILD.txt:** версия исходного кода сборки.

В комплект не включены рабочие CSV/JSON, база, пароли, тестовый календарь или начальное заполнение справочников. Вариант migrate_postgres.sql для этого архива содержит схему без двух исходных блоков заполнения Employees и WorkCalendars; программа и DLL соответствуют указанному коммиту. При обновлении существующие записи сохраняются.

## Перед размещением

Создать резервную копию БД, настроек и папки данных. Обновить .NET 8 Hosting Bundle на IIS. Остановить пул приложения перед заменой DLL.

Для новой установки создать внутреннюю PostgreSQL БД и учётную запись приложения; заполнить ConnectionStrings:PmoNavigatorDb. Приложение не создаёт сервер PostgreSQL или саму БД. Аддитивная схема обновляется при старте при наличии прав; её можно подготовить администратору заранее.

Настроить ProjectsDataPath и доступ учётной записи пула к выгрузкам. Существующую папку wwwroot/data с состоянием приложения и файлами при обновлении не удалять и не заменять тестовыми файлами. Если это новая установка, подготовить нужные выгрузки и согласованный справочник сотрудников со ставками отдельно.

Разместить полный дневной календарь 1С/Qlik и настроить WorkCalendarPath. Проверить права чтения файла. Без него новые часы и отпуск по датам не рассчитываются; ввод процентов остаётся доступен.

Настроить Windows-аутентификацию и согласованный круг пользователей. Сверить фактические имена входа владельца, Александра Кота и Виктории Ануфриёнок с массивами Feedback:AdminLogins и PeriodLocks:Managers. Не выдавать привилегии по имени, введённому в форме.

При размещении по виртуальному пути сохранить существующую настройку PATH_BASE; локальная проверка выполнена с `/pmo-nav`. Реальная Windows-аутентификация, сетевые права и почтовые/AD-идентификаторы проверяются на внутреннем стенде.

## Проверить после установки

- **Календарь:** месяц полностью заполнен, праздник имеет 0 часов, сокращённый день и рабочая суббота совпадают с источником.
- **Отпуск:** сотрудник на ставке 0,25, период через границу месяцев, сохранение, изменение и удаление всего периода.
- **Защита:** обычный пользователь не может скачать обращения или открыть/закрыть месяц; назначенные ответственные могут управлять периодами.
- **Совместимость:** портфель, Ганта, документы, справка, ручной тур, ресурсный план и экспорт открываются по внутреннему адресу.

В локальной проверке существующей тестовой БД сохранялось прежнее предупреждение о попытке ALTER TYPE колонки, используемой представлением. Новые таблица и колонка успешно создавались; рабочие сценарии проверены. При миграции существующей внутренней БД администратору нужно отдельно проверить журнал, а не считать любое предупреждение безвредным.

Рабочий календарь и персональный вход на Render в комплект автоматически не добавляются. Реальный импорт сотрудников/истории и план-факт остаются отдельными задачами.
