# Мастер-план: правила данных и проверка

## Расчёт

- 100% означает всю норму индивидуальной ставки. При ставке 0,25 и норме полного месяца 160 часов: 50% = 20 часов = 0,125 FTE.
- Свободно FTE = ставка − сумма запланированных FTE. Полная загрузка даёт ровно ноль; отрицательный остаток показывает превышение, а не обнуляется.
- Все активные записи справочника включены в месячную сетку, даже если назначений нет. Разные отделы одного человека должны иметь отдельные согласованные плановые записи, например разные «Имя в SD». Не объединять их по ID SD или сокращённому ФИО.
- Отпуск и операционная деятельность также расходуют доступную норму.
- Часы без нормы WorkCalendars или ранее сохранённого снимка нормы не выдумываются. Перед рабочим запуском нормы должны быть согласованы с источником 1С.
- При отсутствии ставки свободные FTE и включающие эту запись итоги показаны как неизвестные, не как ноль.
- Для прошлых месяцев используется единственный снимок ставки в назначениях, если он есть. Несогласованные ставки обозначаются предупреждением; полноценная история кадровых изменений требует отдельного источника.

## Совместимость хранения

Существующий `AllocationPercent` остаётся legacy-процентом от полной ставки. Старые строки не переписываются. Новые сохранения дополнительно заполняют:

- `EmployeeAllocationPercent`: процент индивидуальной нормы, до 6 знаков;
- `RateSnapshot`: ставка на момент сохранения;
- `ProjectNameSnapshot`: название проекта на момент сохранения.

FTE нового назначения = EmployeeAllocationPercent × RateSnapshot / 100; старого = AllocationPercent / 100. Это исключает двойное применение ставки. API ввода/истории и пользовательские CSV/XLSX показывают процент индивидуальной нормы. Изменение записи через API теперь принимает этот процент. Прямым интеграциям нельзя трактовать legacy-колонку БД как новый пользовательский процент.

Миграция PostgreSQL добавляет только новые столбцы. Для SQL Server перед обновлением приложения выполнить `Database/resource_master_mssql.sql`. Тип специалиста поддержан в API сотрудников и необязательной колонке `EmployeeType` CSV-импорта.

## Границы этой версии

Мастер-план читает назначения из базы Навигатора, не из Qlik. Рабочие Excel, история и персональные справочники этой правкой не публикуются и автоматически не импортируются. Для загрузки истории нужен отдельный согласованный импорт в защищённую БД. Условные разработчики и нераспределённые часы нельзя импортировать как сотрудников или как проценты. План-факт и нехватка из SD требуют отдельного подключения их данных; текущий экран их не имитирует.

В старой миграции уже были начальные календарь и справочник со ставками 1. Эта версия не подтверждает правильность этих начальных значений и не заменяет их рабочими Excel автоматически. До использования аналитики для решений нужно загрузить утверждённые ставки, отделы/секторы и календарь. Старые назначения без снимка ставки не позволяют восстановить достоверную историческую ставку из одной текущей записи справочника.

## Проверки на изолированной тестовой базе

Проверить ставку 0,25, проценты и часы в обе стороны, запрет превышения 100%, старую запись без новых полей, нулевой остаток без поправки 100,01, сотрудника без назначений, неизвестную норму, фильтры отдела/сектора/руководителя/типа, сортировку проектов, переключение FTE/часов, экспорт, историю, ошибки диапазона и виртуальный каталог IIS. Не запускать тестовые записи на рабочей БД.

Автотесты: `tests/resource-master/fixtures.sql` (защищён проверкой имени изолированной БД) и `tests/resource-master/check.mjs` (HTTP на 127.0.0.1:5088/pmo-nav). SQL очищает только синтетические строки с префиксом QA; сначала запускать fixture, затем Node-тест.

Проверено локально на опубликованной сборке .NET 8 и PostgreSQL: расчёт 0,25 ставки, 20 часов = 50%, свободные 0 и 0,125 FTE, старая запись 12,5% полной ставки → 50% индивидуальной, ограничение 100% включая параллельные запросы, ошибки периода, неизвестная ставка/календарь, CSV и XLSX. В Playwright проверены ввод/сохранение, фильтры, смена месяца сортировки, FTE/часы, детализация, закрытие и повторное открытие, адаптация 375px и 1440px. Отрицательный ресурс показан числом −0,05, ошибки загрузки очищают прежнюю таблицу.

В существующих зависимостях сборка сообщает предупреждения безопасности для Microsoft.AspNetCore.Authentication.Negotiate 8.0.0; обновление этой зависимости и проверка Windows-аутентификации остаются отдельной задачей перед рабочим IIS. Локальный тест виртуального пути не заменяет проверку на самом IIS.
