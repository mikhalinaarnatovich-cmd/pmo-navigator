# PMO Навигатор

**Единый портфель проектов проектного офиса: статусы, команды, документы, скоринг ПК и ресурсный план — в одном окне.**

Веб-приложение на ASP.NET Core 8, которое объединяет данные из Service Desk, файлового хранилища
документов и HR-справочника и показывает их на удобных экранах для РП, ПК и руководителей.

🔗 **Тестовый стенд:** https://pmo-navigator.onrender.com/
*(бесплатный хостинг Render — при первом открытии после простоя подождите ~10 секунд)*

## Возможности

### 📊 Дашборд
- Счётчики портфеля: всего активных, в работе, требуется вмешательство, есть риски, на паузе, жёсткие дедлайны, завершено
- Графики: здоровье портфеля, по статусам, по типам (L1/L2/L3), по отделам
- **Матрица скоринга по методике ПК**: ось X — итоговый балл (0–5), ось Y — стратегическая важность,
  размер пузыря — сложность и риски, цвет — здоровье. Тултип при наведении, мультивыбор проектов.
  Расчёт совпадает с Qlik до сотых.

### 📁 Карточка проекта
- Команда (участники и роли), цель, даты, ссылка в SD
- **Документы** — файлы по этапам жизненного цикла, превью (PDF/изображения/текст) и скачивание
- **Полнота** — автопроверка обязательных документов по Регламенту УП с учётом уровня проекта (L1/L2/L3)
- Ганта проекта: план, факт, активность по этапам

### 🏛 Экран ПК
- Таблица проектов со скорингом и RAG-статусом
- Inline-комментарии ПК (сохраняются и видны всем)

### 🗂 Портфель и Ганта
- Главный экран **Портфель**: таблица всех проектов + папки-статусы слева. «Все» по умолчанию = все кроме Завершён/Отменён
- Поиск и фильтры в тулбаре (Отдел, Приоритет, РП, Заказчик, Куратор) работают аддитивно с папками-статусами
- Отдельная вкладка **Ганта портфеля**: диаграмма по всему портфелю с масштабом Квартал / Полугодие / Год / Весь портфель

### ✅ Контроль документов
- Совокупная проверка ключевых документов по всем активным проектам (включая «На паузе»):
  1. **Статус-отчёт за текущий месяц** — по дате модификации файла в папке «3. Исполнение и Контроль»
  2. **Инициация без бизнес-инициативы** (для L1 — Паспорт, по Регламенту УП)
  3. **Завершение без итогового отчёта**

### 📝 Запросы на изменение
- Отдельный реестр запросов на изменение по проектам

### 👥 Ресурсный план
- Ввод загрузки в часах или процентах (автопересчёт по производственному календарю)
- **Лимит = ставка сотрудника (FTE) × 100%** — многоставочникам можно больше 100%
- Виды деятельности: Проект / Операционная / Отпуск
- Статусы заполнения, фильтр «Моя команда», блокировки периодов по отделам/секторам
- Журнал аудита (кто, когда, что изменил), история внесений сотрудника
- Экспорт в CSV и Excel (ClosedXML), аналитика по проектам/сотрудникам/месяцам

## Обратная связь

Кнопка рядом со справкой открывает текстовую форму, список обращений и экспорт
в Excel. Сообщения сохраняются в `dbo.feedback`, не в папке `wwwroot`.
На PostgreSQL таблица создаётся при запуске существующим скриптом миграции.
Для установки на MS SQL отдельно предусмотрен `Database/feedback_mssql.sql`.
Таблицу обратной связи необходимо включать в резервное копирование базы.

Текущий режим по согласованию с владельцем:
- **Render: открытая проверка.** `Feedback:AllowAnonymousReviewOnRender = true`
  работает только при серверной переменной `RENDER=true`. Любой посетитель теста
  может отправить сообщение, увидеть список и выгрузить Excel. В интерфейсе есть
  предупреждение: использовать только тестовые данные.
- **IIS:** просмотр и экспорт разрешены только аутентифицированной учётной записи
  из `Feedback:AdminLogins` (сейчас `TP\arnatovich_m`). Сравнивается полный логин,
  не имя из формы и не заголовок запроса. Кнопки на этапе проверки не скрыты,
  но сервер запрещает неразрешённый доступ.
- **После приёмки:** установить `Feedback__AllowAnonymousReviewOnRender=false`
  в окружении Render либо отключить параметр в конфигурации и перезапустить
  приложение. На анонимном Render после этого список, экспорт и отправка закрыты.
  Не включать тестовый режим на рабочем IIS.

Вложения пока не поддерживаются. Отправка защищена antiforgery-токеном,
ограничена 10 запросами в минуту на пользователя/IP и не дублируется при повторе
того же идентификатора запроса. В Excel входят все выбранные фильтрами записи
(до 10 000 за одну выгрузку), а не только текущая страница из 50 строк.
Даты и фильтры используют часовой пояс Минска. Поля обращений выгружаются как
текст, без выполнения формул из сообщений.

## Локальный предпросмотр документов

DOCX и XLSX открываются в браузере без Office Online Viewer и без установки
конвертера на IIS. При публикации обязательно переносить `wwwroot/js/file-preview.js`,
`wwwroot/office-preview/` и `wwwroot/vendor/office-preview/` вместе с приложением.
Стандартная публикация ASP.NET Core включает эти файлы автоматически.

Просмотрщик получает файл через существующий `api/file/download` с текущими
учётными данными браузера. Office-документ обрабатывается в изолированном iframe:
внешние подключения запрещены CSP; библиотеки загружаются локально.
Оригинал не изменяется. Путь приложения (например `/pmo-nav`) учитывается
для запросов и статических файлов. Подключение к БД для просмотра не требуется.

- DOCX: текст, изображения, таблицы, колонтитулы и масштаб 50–150%;
  оформление и разбиение на страницы могут отличаться от Word.
- XLSX: переключение видимых листов, значения и объединения; без пересчёта
  формул, диаграмм и точного воспроизведения оформления.
- Лимиты просмотра: файл до 20 МБ; распакованный размер по метаданным ZIP
  до 100 МБ; до 10 000 записей архива; до 1000 строк и 100 столбцов листа.
- DOC, XLS, PPT/PPTX и защищённые/повреждённые файлы: скачивание оригинала.
- Если файл не открывается, сначала проверить скачивание оригинала и доступ
  процесса IIS к папке документов. Не включать анонимный внешний доступ к
  рабочим документам ради предпросмотра.

Версии библиотек и лицензии: `wwwroot/vendor/office-preview/README.md`.

## Источники данных

| Источник | Что хранит | Как обновляется |
|----------|-----------|-----------------|
| `projects.csv` | Проекты (~300 строк, 36 колонок, 1 строка = 1 проект) | Конвертер `convert_projects.py` из XLSX-выгрузки SD → кнопка «Обновить» в приложении |
| `members.csv` | Команды проектов (ProjectId, Person, Role) | Вместе с projects.csv |
| `pk_comments.json` | Комментарии ПК | Пишется приложением |
| PostgreSQL (схема `dbo`) | Сотрудники, ресурсный план, блокировки, аудит, календарь, обратная связь | Живая БД; миграция при старте из `Database/migrate_postgres.sql` |
| Файловая папка | Документы проектов | Прод: `Z:\Документы\Common\РМО`. Тест: `ProjectDocs/` в репозитории (fallback, если диск недоступен) |

**Прод-пути** (прописаны в `appsettings.json`):
- Документы проектов (`ProjectsBasePath`): `Z:\Документы\Common\РМО`
- CSV-выгрузки (`ProjectsDataPath`): `\\Srv-fs10\qlik\Проектный офис\данные для навигатора`

**Важно про выгрузку SD:** исходный XLSX содержит декартово произведение «проекты × участники × роли»
(84 908 строк). Конвертер сжимает его до одной строки на проект и выносит участников в `members.csv`.
Составы команд из выгрузки не используются (там баг — у каждого проекта весь отдел); берутся из
проверенного `members.csv`.

## Технологии

| Компонент | Технология |
|-----------|-----------|
| Backend | ASP.NET Core 8 (MVC + Web API) |
| База данных | PostgreSQL (EF Core + Npgsql); автоопределение MS SQL по строке подключения |

## Переменные окружения

| Переменная | Описание |
|-----------|----------|
| `ConnectionStrings__PmoNavigatorDb` | Строка подключения к PostgreSQL (или MS SQL — провайдер определяется автоматически) |
| `DISABLE_WINDOWS_AUTH` | `true` на тесте (Render) — без AD. На IIS не задавать |
| `ProjectsBasePath` | Папка документов (по умолчанию `Z:\Документы\Common\РМО`; если недоступен — fallback на `wwwroot/test-docs`) |
| `ProjectsDataPath` | Папка с CSV-выгрузками (по умолчанию `\\Srv-fs10\qlik\Проектный офис\данные для навигатора`; если пусто — fallback на `wwwroot/data`) |
| `ASPNETCORE_URLS` | Порт (на Render — `http://+:10000`) |

## Запуск

**Локально:**
```bash
dotnet restore
dotnet run   # нужна PostgreSQL с заданной строкой подключения
```

**Деплой на Render:** Web Service из репозитория → Dockerfile соберётся сам → добавить
`ConnectionStrings__PmoNavigatorDb` и `DISABLE_WINDOWS_AUTH=true` → таблицы создадутся при старте.

**Деплой на IIS (прод):** `dotnet publish` → сайт в IIS → .NET 8 Hosting Bundle →
в `appsettings.json` прописаны `Z:\Документы\Common\РМО` и `\\Srv-fs10\qlik\Проектный офис\данные для навигатора`, Windows Auth включается автоматически
(не задавать `DISABLE_WINDOWS_AUTH`). Пул приложения — под доменной учёткой с доступом к обеим сетевым папкам.
